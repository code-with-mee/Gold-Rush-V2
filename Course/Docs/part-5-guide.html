GOLD RUSH · Part 5

Mobile controls

Gold Rush is made for phones. Here you will see how the on-screen joystick and the drag-to-look area work, how they share the code with the keyboard and mouse, how to test touch in the Editor, and how to build the game for Android or iOS.

1The screen is split in two

AreaScriptWhat a finger does there
Left halfVirtualJoystickA stick appears under the thumb. Push it to walk, push to the edge to sprint.
Right halfTouchLookAreaDrag to turn the camera.
ButtonsButtonFX, DayNightButtonPause and the sun/moon button, drawn on top.

Both areas are invisible full-height UI images. GameUI.Build() creates them first, so they are drawn under everything else, and buttons on top still get their taps:

Scripts/UI/GameUI.cs – Build() 
TouchLookArea.Create(canvasRt);            // right half
Joystick = VirtualJoystick.Create(canvasRt); // left half

Because each area remembers only one finger (pointerId), you can move with your left thumb and look with your right thumb at the same time.

All UI sizes are in reference pixels on a 1920 × 1080 canvas (the CanvasScaler stretches them to the real screen). So a stick radius of 120 looks the same on every phone.

2The virtual joystick

VirtualJoystick uses three uGUI event interfaces: IPointerDownHandler, IDragHandler and IPointerUpHandler. Unity calls the matching method when a finger (or the mouse) goes down, moves and goes up.

  1. OnPointerDown: remember this finger, and move the stick base to where the thumb is. The stick fades in.
  2. OnDrag: work out how far the thumb is from the base, and turn that into Value:
Scripts/UI/VirtualJoystick.cs 
public void OnDrag(PointerEventData e)
{
    if (e.pointerId != pointer) return;
    Vector2 d = Local(e) - stickBase.anchoredPosition;
    // the stick follows the thumb if it drags far away
    if (d.magnitude > radius * 1.6f)
    {
        stickBase.anchoredPosition += d.normalized * (d.magnitude - radius * 1.6f);
        d = Local(e) - stickBase.anchoredPosition;
    }
    Vector2 c = Vector2.ClampMagnitude(d, radius);
    knob.anchoredPosition = c;
    Vector2 v = c / radius;
    Value = v.magnitude < 0.12f ? Vector2.zero : v;
}
  • ClampMagnitude(d, radius) keeps the knob inside the ring (radius 120).
  • c / radius turns pixels into a value from 0 to 1. Half-way pushed means half speed.
  • Dead zone: under 0.12 counts as zero, so a resting thumb does not make the hero creep.
  • Follow the thumb: if your thumb slides far away (more than 1.6 × the radius), the base slides after it. You never “lose” the stick.
  1. OnPointerUp: Release() sets Value to zero and the stick fades out.

PlayerMotor.ReadInput() (Part 1) reads joystick.Value. If a WASD or arrow key is held, the keyboard wins. So the same movement code works on a computer and on a phone.

3Sprint by pushing to the edge

Scripts/Gameplay/PlayerMotor.cs 
bool wantSprint = canMove && mag > 0.2f && ((joystick && joystick.Held && joystick.Value.magnitude > 0.9f) || Input.GetKey(KeyCode.LeftShift) || Input.GetKey(KeyCode.RightShift));

Phones have no Shift key, so the stick doubles as the sprint button: past 90% of the radius you sprint. The ring turns orange at the same point (in VirtualJoystick.Update()), so the player can see it.

4Look by dragging

TouchLookArea does not turn the camera itself. It only collects how far the finger moved, like a mailbox:

Scripts/UI/TouchLookArea.cs 
public static Vector2 Consume()
{
    var a = accumulated;
    accumulated = Vector2.zero;
    return a;
}
public void OnDrag(PointerEventData e)
{
    if (e.pointerId != pointer) return;
    accumulated += e.delta;
    Place(e);
}

Every frame, the camera empties the mailbox and turns:

Scripts/Gameplay/ThirdPersonCamera.cs 
Vector2 look = TouchLookArea.Consume() * (1920f / Mathf.Max(1, Screen.width));
yaw += look.x * touchSensitivity;
pitch -= look.y * touchSensitivity * 0.8f;

The 1920f / Screen.width part makes a swipe across half the screen turn the camera the same amount on a small phone and on a big tablet. touchSensitivity is 0.16 degrees per reference pixel.

5Mouse lock: computer only

Scripts/Gameplay/GameManager.cs 
/// <summary>True on computers: hide + lock the cursor while playing so the mouse turns the camera.</summary>
static bool UseMouseLook => !Application.isMobilePlatform && !Input.touchSupported;

On a computer the cursor is hidden and locked after the countdown, like most PC 3D games, so moving the mouse turns the camera. Esc pauses and frees it. On a phone none of that happens. When the app goes into the background, the game pauses itself (OnApplicationPause).

6Buttons that feel good

Every button made by UIKit gets a ButtonFX component. It makes the button react: it grows a little on hover, shrinks or sinks when pressed, and plays the "click" sound. On touch screens this small feedback matters a lot, because there is no mouse pointer.

DayNightButton is a good example of an event: it subscribes to DayNight.Changed and swaps the sun and moon icon whenever the time of day changes, whether you tapped it or pressed N.

void OnEnable() { DayNight.Changed += OnChanged; }
void OnDisable() { DayNight.Changed -= OnChanged; }

7Test touch in the Editor

In the normal Game view the cursor is locked after the countdown, so you cannot drag the joystick with the mouse. Use the keyboard there, or use the Simulator.
  1. At the top of the Game view, change the Game dropdown to Simulator.
  2. Choose a phone from the device list and rotate it to landscape (the game is landscape only).
  3. Press Play. A mouse click now acts like a finger. Drag on the left half to move and on the right half to look.

In the Simulator the game should also show the touch version of the controls hint. If it still hides the cursor, the Simulator is not reporting a mobile device: check that a phone (not a desktop) is selected.

The best test is still a real phone (step 8).

8Build for a phone

Most settings are already done: landscape only (left and right), and for Android the package name com.itstep.goldrush, minimum Android 8.0 (API 26), IL2CPP and ARM64.

Android

  1. In Unity Hub, add the Android Build Support module (with OpenJDK and the Android SDK & NDK) to Unity 6000.6.10f1.
  2. File → Build Profiles → Android → Switch Platform.
  3. Check the scene list: MainMenu, Level1–Level4, Game. (Running Gold Rush → Setup Project writes this list for you.)
  4. On the phone, turn on Developer options and USB debugging, then connect it with a cable.
  5. Build And Run.
If several students install on the same phone, give each build its own package name in Player Settings → Other Settings, for example com.itstep.goldrush.anna. Otherwise each install replaces the last one.

iOS (needs a Mac with Xcode)

  1. Add the iOS Build Support module and switch the platform to iOS.
  2. In Player Settings → Other Settings, change the Bundle Identifier. It is still the URP template default. Also set your Signing Team ID.
  3. Build. Unity makes an Xcode project. Open it in Xcode, choose your device, and press Run.
Setup Project sets the orientation back to landscape every time it runs. If you want a portrait version, change GoldRushSetup.cs too.

9Try it

A smaller stick

In VirtualJoystick.cs, change public float radius = 120f; to 80f. A shorter thumb push now gives full speed and sprint.

A bigger dead zone

In OnDrag, change 0.12f to 0.35f. Small wiggles no longer move the hero.

Easier sprint

Change joystick.Value.magnitude > 0.9f in PlayerMotor.cs to > 0.7f. Make the same change in VirtualJoystick.Update(), so the orange ring still matches.

Faster look

In ThirdPersonCamera.cs, change touchSensitivity = 0.16f to 0.3f, and test in the Simulator. For the computer, change mouseSensitivity.

Inverted look

Change pitch -= look.y * ... to pitch += look.y * .... Some players like dragging up to look down.

A red sprint ring

In VirtualJoystick.Update(), change UIKit.Orange to UIKit.Red.

Checklist

  • I know why the keyboard and the joystick can share one movement function.
  • I can test touch with the Simulator, and I know what to change before building for iOS.
