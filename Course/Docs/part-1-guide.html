GOLD RUSH · Part 1

The arena and a walking hero

Every game needs a place to play and someone to play as. In this part you open the project, find out how a level is made (from a scene or from a seed), and see how the hero walks, sprints and is followed by a third-person camera.

1Open the project

  1. Install Unity 6000.6.10f1 (or newer) from Unity Hub. Older versions may not open the project.
  2. Unity Hub → Add → Add project from disk → choose the GoldRushDemo folder.
  3. When it has opened, use the top menu Gold Rush → Play. The game always starts from the main menu, whatever scene is open.
If you see pink objects, a “GoldRushAssets missing” message in the Console, or no characters, run Gold Rush → Setup Project. It creates the materials, animator controllers, scenes and build settings. It is safe to run again.

2The scenes

Look in Assets/GoldRush/Scenes/:

SceneWhat is inside
MainMenu.unityOnly one GameObject, GoldRushMenu. Its script builds the whole menu in Start().
Level1.unity … Level4.unityThe four campaign levels, saved as real scenes with walls, blocks, lamps and marker objects. You can edit them in the Scene view.
Game.unityOnly one GameObject, GameManager. There is no level in it: the level is generated from code. Used by the Daily Rush.

Almost nothing else is saved in the scenes. The hero, the camera, the lights, the coins, the monsters and all of the UI are created by code when you press Play. That is why the Hierarchy looks almost empty in Edit mode and full in Play mode.

Each project folder has one job: Scripts/Core (data and helpers), Scripts/World (level, props, coins, gate), Scripts/Gameplay (rules, player, monsters, camera), Scripts/UI, Scripts/Audio, Scripts/Level (the marker components) and Editor (tools for the Gold Rush menu).

3Two ways to make a level

Every level starts as a row of data in Scripts/Core/Data.cs:

Scripts/Core/Data.cs 
new LevelDef { title = "Training Yard", subtitle = "Learn the ropes", seed = 101, scene = "Level1",
               size = 32, coins = 6, patrollers = 2, powerUps = 1, props = 14, bigRocks = 1,
               enemySpeed = 0.9f, parTime = 40 },

When a level starts, GameManager.Build() decides where the arena comes from:

Scripts/Gameplay/GameManager.cs 
// hand-made level in this scene? otherwise generate one from the level's seed
var handMade = FindAnyObjectByType<LevelScene>();
layout = handMade ? LevelFromScene(handMade) : LevelBuilder.Build(Def);
Player = PlayerMotor.Create(layout.spawn, layout.spawnYaw);
Cam = ThirdPersonCamera.Create(Player.transform, layout.spawnYaw);

Hand-made (Levels 1–4)

The level has scene = "Level1", so Level1.unity is loaded. It contains a LevelScene object, so LevelFromScene() reads the walls and markers that are already in the scene.

Generated (Daily Rush)

No scene name, so Game.unity is loaded. There is no LevelScene, so LevelBuilder.Build() creates floor, walls, blocks and lamps from code. A seed drives the random numbers, so the same seed always gives the same level.

The four level scenes were made by that same generator, then saved and polished by hand (Gold Rush → Level Design → Rebuild Level Scenes is the tool that created them).

Because Levels 1–4 are saved scenes, changing size, seed, coins, props or the monster counts in Data.cs does not change them. Those numbers are only used when a level is generated. What does change them from Data.cs: title, subtitle, enemySpeed, parTime, lives and night.

5The hero: CharacterController

PlayerMotor.Create() makes a GameObject named Player, adds a CharacterController (a capsule that moves and collides without physics forces), and puts the hero model inside it (Part 2).

Every frame, PlayerMotor.Update() reads the input:

Scripts/Gameplay/PlayerMotor.cs 
Vector2 ReadInput()
{
    Vector2 v = joystick ? joystick.Value : Vector2.zero;
    float kx = (Input.GetKey(KeyCode.D) || Input.GetKey(KeyCode.RightArrow) ? 1 : 0) - (Input.GetKey(KeyCode.A) || Input.GetKey(KeyCode.LeftArrow) ? 1 : 0);
    float ky = (Input.GetKey(KeyCode.W) || Input.GetKey(KeyCode.UpArrow) ? 1 : 0) - (Input.GetKey(KeyCode.S) || Input.GetKey(KeyCode.DownArrow) ? 1 : 0);
    if (kx != 0 || ky != 0) v = new Vector2(kx, ky).normalized;
    return Vector2.ClampMagnitude(v, 1f);
}

kx is right minus left, ky is up minus down. So D gives (1, 0) and W+D gives a diagonal. .normalized keeps diagonal movement from being faster. The joystick (Part 5) gives the same kind of Vector2.

Then the input is turned to match the camera, so W always means “away from the camera”:

float yaw = cam ? cam.Yaw : 0f;
Vector3 dir = Quaternion.Euler(0, yaw, 0) * new Vector3(input.x, 0, input.y);

The hero speeds up smoothly toward the target speed (Vector3.MoveTowards with acceleration = 20), turns to face where it is going, falls with gravity, and finally moves:

if (cc.isGrounded && vy < 0) vy = -2f; else vy -= 25f * dt;
knock = Vector3.Lerp(knock, Vector3.zero, 1f - Mathf.Exp(-5f * dt));
if (cc.enabled) cc.Move((velocity + knock + Vector3.up * vy) * dt);

6Sprint and stamina

Sprinting = wantSprint && !Exhausted && Stamina > 0f;
if (Sprinting)
{
    Stamina = Mathf.Max(0f, Stamina - dt * 0.3f);
    if (Stamina <= 0f) Exhausted = true;
}
else Stamina = Mathf.Min(1f, Stamina + dt * (mag > 0.1f ? 0.18f : 0.32f));
  • Stamina goes from 1 (full) to 0. Sprinting uses 0.3 per second, so a full bar lasts about 3.3 seconds.
  • It refills faster when you stand still (0.32/s) than when you walk (0.18/s).
  • When it hits 0 you are Exhausted and cannot sprint again until it is back above 0.35. The HUD bar shows RUN or TIRED.

7The third-person camera

ThirdPersonCamera orbits around the hero. Two angles describe where it is: yaw (left/right around the hero) and pitch (how high it looks down from).

Scripts/Gameplay/ThirdPersonCamera.cs – LateUpdate() 
if (Cursor.lockState == CursorLockMode.Locked || Input.GetMouseButton(1))
{
    yaw += Input.GetAxis("Mouse X") * mouseSensitivity;
    pitch -= Input.GetAxis("Mouse Y") * mouseSensitivity * 0.8f;
}
if (Input.GetKey(KeyCode.Q)) yaw -= 110f * dt;
if (Input.GetKey(KeyCode.E)) yaw += 110f * dt;
distance = Mathf.Clamp(distance - Input.mouseScrollDelta.y * 0.5f, 4f, 11f);
  • It runs in LateUpdate(), after the hero has moved in Update(), so the camera never lags one frame behind.
  • Yaw and pitch are smoothed with SmoothDamp. Pitch is kept between 4° and 62°.
  • Wall avoidance: rays are cast from the hero toward the camera. If a wall is in the way, the camera moves in closer so you never look at the inside of a wall.
  • Shake(amplitude, duration) adds a short shake. The game uses it when you are hit or the gate opens.

8Try it

Tune the hero live (no code)

Open Level1.unity and press Play. Press Esc to pause and free the mouse. Select Player in the Hierarchy. In Player Motor, set Walk Speed to 10 and Turn Speed to 90, then click RESUME. The hero runs very fast and turns in wide arcs. The values reset when you stop Play, because Player is created by code. To keep a change, edit the number in PlayerMotor.cs.

A longer sprint

In PlayerMotor.cs, change Stamina - dt * 0.3f to Stamina - dt * 0.1f. You can now sprint for about 10 seconds.

A higher camera

In ThirdPersonCamera.cs, set distance = 10f and pitch = 40f. You now see more of the arena from above. Values above 11 for distance do nothing, because the zoom line clamps it to 4–11 every frame.

A level from a seed

Open Game.unity and press Play. Level 1's settings are generated by LevelBuilder, so it looks different from Level1.unity. Stop, change Level 1's seed = 101 to seed = 7 in Data.cs, and press Play in Game.unity again: a new layout. Also try props = 40 or size = 44.

Build onto a level

Open Level1.unity. Drag Prefabs/Level/Blocks/Wall_8m onto Level 1 - Training Yard/Static and place it in the arena. Press Play: the hero bumps into it. Keep new walls under Static, so they are part of the NavMesh the monsters use.

Move the start point

Select Gameplay/PlayerSpawn. Move it and rotate it around Y. Press Play: the hero and the camera start there, facing the same way.
