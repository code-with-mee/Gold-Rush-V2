GOLD RUSH · Phase 3

The player

You will set up the hero model, build its Animator Controller by hand (idle, walk, run and four action animations) and make a Player prefab that you control with the keyboard. At the end the hero walks with WASD, sprints with Shift, and the right animation plays at every speed.

1What you need

  • Phase 2 is finished: the Level1 scene has a floor, walls and blocks, and an empty marker called PlayerSpawn. (Or import GoldRush_Phase02_Level.unitypackage.)
  • The hero model is in Assets/GoldRush/Art/Characters/Hero/Hero.fbx (from Phase 0).
  • Active Input Handling is Both (Phase 0). The scripts read the keyboard with the classic Input class.

Open Assets/GoldRush/Scenes/Level1.unity.

2Hero import settings

An FBX file holds the 3D model, its skeleton (the "rig") and its animations. You tell Unity how to read it in the Import Settings.

  1. In the Project window, click Art/Characters/Hero/Hero.fbx. The Inspector shows four tabs: Model, Rig, Animation, Materials.
  2. Model tab: untick Import Cameras and Import Lights. Click Apply.
  3. Rig tab: set Animation Type = Generic. Set Avatar Definition = Create From This Model. Click Apply.
  4. Materials tab: set Material Creation Mode = Import via MaterialDescription and Location = Use Embedded Materials. Click Apply.
Generic means "use the skeleton as it is". (Humanoid is for sharing animations between human models. We do not need it.)

3The animation clips

The FBX has many animations (clips). We use 7 of them. Idle, walk, run and wave must loop (play again and again). The others play once.

  1. Open the Animation tab. Make sure Import Animation is ticked.
  2. In the Clips list, click a clip from the table, for example Idle.
  3. If its name starts with CharacterArmature|, delete that part in the name field, so the name is only Idle. (In the starter package the names are already short.)
  4. Check Loop Time and Loop Pose as in the table. Tick or untick them if they are different.
  5. Do the same for all 7 clips in the table. Leave the other clips (Duck, Jump, Gun…) as they are.
  6. Click Apply at the bottom.

4Create the Animator Controller

An Animator Controller decides which clip plays. Scripts talk to it with parameters: a number (Float) or a one-time signal (Trigger).

  1. In the Project window, open Assets/GoldRush/Animations.
  2. Right-click → Create → Animation → Animator Controller. Name it Hero.
  3. Double-click Hero. The Animator window opens.
  4. On the left, open the Parameters tab. Click + and add these 5 parameters. The names must be exactly like this (capital letters too):
NameTypeMeaning
SpeedFloat0 = idle, 0.5 = walk, 1 = run
AttackTriggerpunch
HitTriggera monster hit the hero
WinTriggerlevel finished
DieTriggercaught, game over
The monsters in Phase 7 use the same 5 parameter names. The scripts send these names, so a typo (speed, Hit with a space) means "nothing happens".

5The Locomotion blend tree

A blend tree mixes clips by a number. With Speed = 0 the hero stands, with 0.5 it walks, with 1 it runs, and values in between mix two clips smoothly.

  1. In the Animator window, right-click the empty grid → Create State → From New Blend Tree.
  2. Click the new state. In the Inspector, rename it Locomotion. It is orange: it is the default state (the one that plays first).
  3. Double-click Locomotion to go inside it. Click the Blend Tree node.
  4. In the Inspector: Blend Type = 1D, Parameter = Speed.
  5. Under Motion, click + → Add Motion Field three times.
  6. Untick Automate Thresholds.
  7. Fill the three rows. Drag each clip from the Project window (click the small arrow on Hero.fbx to see its clips):
RowMotionThreshold
1Idle0
2Walk0.5
3Run1
  1. Click Base Layer at the top of the Animator window to go back out.

6The action states

Now add one state for each trigger. You will use them in later phases (Win in Phase 6, Hit and Die in Phase 7), but you can test them today.

  1. Right-click the grid → Create State → Empty.
  2. In the Inspector, give it a name from the table and drag its clip into Motion.
  3. Repeat for all four.

7The transitions

A transition is an arrow from one state to another. Any State means "from wherever you are now".

A. From Any State to each action (4 arrows):

  1. Right-click Any State → Make Transition → click Attack.
  2. Click the new arrow. In the Inspector:
    • Untick Has Exit Time (the action starts at once).
    • Open Settings: Transition Duration = 0.1. Untick Can Transition To Self.
    • Under Conditions, click + and choose Attack.
  3. Do the same for Hit, Win and Die (each with its own trigger as condition).

B. Back to Locomotion (3 arrows, not for Die):

  1. Right-click Attack → Make Transition → click Locomotion.
  2. Click the arrow. Keep Has Exit Time ticked. Set Exit Time and Transition Duration from the table. No conditions.
  3. Do the same for Hit and Win.

  • Exit Time 3 = the wave clip loops, so the hero waves 3 times, then goes back to idle.
  • Die has no way back. The hero stays lying on the ground.

8Script: VirtualJoystick (stub)

On phones, the player moves with a touch joystick. That comes in a later phase. But PlayerMotor already reads it, so we need a tiny "stub" now: a placeholder class that compiles and always says "no finger on the stick".

  1. In Assets/GoldRush/Scripts/UI: right-click → Create → Scripting → MonoBehaviour Script. Name it VirtualJoystick.
  2. Open it and replace everything with this code. Save.
using UnityEngine;

namespace GoldRush
{
    /// <summary>
    /// PHASE 3 STUB. The real touch joystick comes in a later phase (touch controls).
    /// For now it only has the two values PlayerMotor reads, and they are always "no touch".
    /// </summary>
    public class VirtualJoystick : MonoBehaviour
    {
        public Vector2 Value { get; private set; }
        /// <summary>True while a finger is on the stick.</summary>
        public bool Held => false;
    }
}
  • namespace GoldRush: all game scripts live in this "family name", so they can find each other.
  • Value is the stick direction. Here it is always (0, 0).
  • A later phase says "replace the whole file". Then the real joystick takes its place, and PlayerMotor does not change.

9Script: PlayerMotor

This script moves the hero. Create Assets/GoldRush/Scripts/Gameplay/PlayerMotor.cs the same way and paste this Phase 3 version. Later phases replace it with bigger versions.

using UnityEngine;

namespace GoldRush
{
    /// <summary>Third-person player: CharacterController movement (collides with props), sprint/stamina,
    /// walk/run animation.
    /// PHASE 3 VERSION: later phases add power-ups, hits, sounds, dust and win/lose poses.</summary>
    [RequireComponent(typeof(CharacterController))]
    public class PlayerMotor : MonoBehaviour
    {
        public float walkSpeed = 5f;
        public float sprintSpeed = 8.2f;
        public float acceleration = 20f;
        public float turnSpeed = 560f;

        [Header("Animation")]
        [Tooltip("Ground speed (m/s) the Walk clip was animated for (measured from the feet).")]
        public float clipWalkSpeed = 0.59f;
        [Tooltip("Ground speed (m/s) the Run clip was animated for (measured from the feet).")]
        public float clipRunSpeed = 0.84f;

        public VirtualJoystick joystick;
        public float Stamina { get; private set; } = 1f;
        public bool Exhausted { get; private set; }
        public bool Sprinting { get; private set; }
        public bool Frozen { get; set; }
        public Vector3 Velocity => velocity;
        public Animator Anim => anim;

        CharacterController cc;
        float animSpeed = 1f;
        Animator anim;
        Vector3 velocity;
        float vy;

        void Awake()
        {
            cc = GetComponent<CharacterController>();
            anim = GetComponentInChildren<Animator>(); // the Animator on the "Model" child
        }

        Vector2 ReadInput()
        {
            Vector2 v = joystick ? joystick.Value : Vector2.zero;
            float kx = (Input.GetKey(KeyCode.D) || Input.GetKey(KeyCode.RightArrow) ? 1 : 0) - (Input.GetKey(KeyCode.A) || Input.GetKey(KeyCode.LeftArrow) ? 1 : 0);
            float ky = (Input.GetKey(KeyCode.W) || Input.GetKey(KeyCode.UpArrow) ? 1 : 0) - (Input.GetKey(KeyCode.S) || Input.GetKey(KeyCode.DownArrow) ? 1 : 0);
            if (kx != 0 || ky != 0) v = new Vector2(kx, ky).normalized;
            return Vector2.ClampMagnitude(v, 1f);
        }

        void Update()
        {
            float dt = Time.deltaTime;
            if (dt <= 0f) return;
            bool canMove = !Frozen;

            Vector2 input = canMove ? ReadInput() : Vector2.zero;
            float yaw = 0f; // Phase 4: the camera decides which way is "forward"
            Vector3 dir = Quaternion.Euler(0, yaw, 0) * new Vector3(input.x, 0, input.y);
            float mag = Mathf.Clamp01(dir.magnitude);

            bool wantSprint = canMove && mag > 0.2f && ((joystick && joystick.Held && joystick.Value.magnitude > 0.9f) || Input.GetKey(KeyCode.LeftShift) || Input.GetKey(KeyCode.RightShift));
            if (Exhausted && Stamina > 0.35f) Exhausted = false;
            Sprinting = wantSprint && !Exhausted && Stamina > 0f;
            if (Sprinting)
            {
                Stamina = Mathf.Max(0f, Stamina - dt * 0.3f);
                if (Stamina <= 0f) Exhausted = true;
            }
            else Stamina = Mathf.Min(1f, Stamina + dt * (mag > 0.1f ? 0.18f : 0.32f));

            float speed = Sprinting ? sprintSpeed : walkSpeed;
            Vector3 targetVel = mag > 0.01f ? dir.normalized * (mag * speed) : Vector3.zero;
            velocity = Vector3.MoveTowards(velocity, targetVel, acceleration * dt);

            if (velocity.sqrMagnitude > 0.05f && !Frozen)
            {
                var targetRot = Quaternion.LookRotation(new Vector3(velocity.x, 0, velocity.z));
                transform.rotation = Quaternion.RotateTowards(transform.rotation, targetRot, turnSpeed * dt);
            }

            if (cc.isGrounded && vy < 0) vy = -2f; else vy -= 25f * dt;
            if (cc.enabled) cc.Move((velocity + Vector3.up * vy) * dt);

            // animation (0 idle, 0.5 walk, 1 run)
            float horiz = new Vector3(velocity.x, 0, velocity.z).magnitude;
            float blend = horiz < 0.1f ? 0f : Mathf.Lerp(0.45f, 1f, Mathf.InverseLerp(2.5f, sprintSpeed, horiz));
            if (anim && anim.runtimeAnimatorController) anim.SetFloat("Speed", blend, 0.15f, dt);
            // play the walk/run cycle as fast as the hero moves, so the feet don't slide
            if (anim && !Frozen)
            {
                float target = PlaybackSpeed(blend, horiz);
                animSpeed = Mathf.Lerp(animSpeed, target, 1f - Mathf.Exp(-5f * dt)); // ease, never jump
                anim.speed = animSpeed;
            }
        }

        /// <summary>Animation playback speed so the feet match the ground.
        /// blend = Animator "Speed" value (0.5 walk .. 1 run), groundSpeed = how fast the hero really moves.</summary>
        float PlaybackSpeed(float blend, float groundSpeed)
        {
            if (groundSpeed < 0.15f) return 1f;
            float natural = Mathf.Lerp(clipWalkSpeed, clipRunSpeed, Mathf.InverseLerp(0.5f, 1f, blend));
            float ratio = groundSpeed / Mathf.Max(0.1f, natural);
            // match most of the stride but keep it gentle: fluid motion matters more than perfect feet
            return Mathf.Clamp(Mathf.Lerp(1f, ratio, 0.7f), 0.8f, 2.2f);
        }
    }
}
  • [RequireComponent(typeof(CharacterController))]: Unity adds a CharacterController if it is missing. A CharacterController is a capsule that moves with cc.Move() and stops at walls, without real physics.
  • ReadInput() reads WASD or the arrow keys into a direction. .normalized makes diagonal moves as fast as straight ones.
  • Sprint: hold Shift → speed goes from 5 to 8.2 m/s. Sprinting uses stamina (1 = full). At 0 the hero is exhausted and walks until stamina is back above 0.35. (The HUD shows it later.)
  • Vector3.MoveTowards(velocity, targetVel, acceleration * dt): the hero speeds up and slows down smoothly (20 m/s²), instead of starting at full speed. RotateTowards turns him toward where he runs, 560° per second.
  • vy is the falling speed. Gravity is 25 m/s². On the ground it stays at -2 so the hero sticks to the floor.
  • Animation: anim.SetFloat("Speed", blend, 0.15f, dt) feeds the blend tree (0 idle … 0.5 walk … 1 run), with a 0.15 s smoothing. PlaybackSpeed() plays the cycle faster when the hero moves faster, so the feet do not slide. clipWalkSpeed / clipRunSpeed are how fast the clips were made to move (measured from the feet).
The line float yaw = 0f; means "forward is always the world's +Z direction". In Phase 4, the camera decides where forward is.

10Script: PlayerSpawn

This marker shows where the hero starts. If you already made it in Phase 2, skip this step.

  1. Create Assets/GoldRush/Scripts/Level/PlayerSpawn.cs and paste:
using UnityEngine;

namespace GoldRush
{
    /// <summary>Where the hero starts. The blue arrow shows which way the hero (and camera) faces.</summary>
    public class PlayerSpawn : MonoBehaviour
    {
        void OnDrawGizmos()
        {
            Gizmos.color = new Color(0.25f, 0.6f, 1f);
            Gizmos.DrawWireSphere(transform.position + Vector3.up * 0.7f, 0.5f);
            Gizmos.DrawLine(transform.position + Vector3.up * 0.1f, transform.position + Vector3.up * 0.1f + transform.forward * 2f);
            Gizmos.DrawSphere(transform.position + Vector3.up * 0.1f + transform.forward * 2f, 0.15f);
        }
    }
}
  1. Select the PlayerSpawn marker in the Hierarchy → Add Component → PlayerSpawn.
  • OnDrawGizmos draws only in the Scene view: a blue ball and a blue arrow. The arrow is the way the hero will face. It is invisible in the game.
  • From Phase 5 on, the GameManager moves the Player to this marker when the level starts.

11Create the Player object

  1. GameObject → Create Empty. Name it Player.
  2. Transform: Position 0, 0, 0, Rotation 0, 0, 0, Scale 1, 1, 1.
  3. Add Component → Character Controller. Set the values from the table.
  4. At the top of the Inspector, set Layer = Ignore Raycast.
Character ControllerValue
Slope Limit50
Step Offset0.35
Skin Width0.05
Center0, 0.695, 0
Radius0.36
Height1.35
  • Height 1.35: the hero is 1.35 m tall. Center Y 0.695 = half the height + 0.02, so the bottom of the capsule is at the feet.
  • Step Offset 0.35: the hero can walk up small steps up to 35 cm.
  • Ignore Raycast layer: in Phase 4 the camera sends rays to find walls. With this layer, the rays fly through the player.

12Add the hero model

  1. Drag Hero.fbx from the Project window onto Player in the Hierarchy. It becomes a child.
  2. Rename the child Model.
  3. Transform of Model: Position 0, 0, 0, Rotation 0, 0, 0, Scale 0.36, 0.36, 0.36.
  4. Look at the Scene view. The hero must fit inside the green capsule of the Character Controller: feet at the bottom, head at the top. If not, change the Scale a little (same number in X, Y, Z).
  5. Model already has an Animator component. Set:
    • Controller = Hero (from Animations)
    • Avatar = HeroAvatar (normally already set)
    • Apply Root Motion = off
    • Culling Mode = Always Animate
Apply Root Motion off: the script moves the player, not the animation. If it is on, the hero "walks away" from his capsule.

13Add PlayerMotor and save the prefab

  1. Select Player → Add Component → PlayerMotor.
  2. Check the values: Walk Speed 5, Sprint Speed 8.2, Acceleration 20, Turn Speed 560, Clip Walk Speed 0.59, Clip Run Speed 0.84. Leave Joystick empty.
  3. Make sure the layer of Player and Model is Ignore Raycast: select Player, set the Layer again, and click Yes, change children.
  4. Drag Player from the Hierarchy into Assets/GoldRush/Prefabs/Gameplay. It turns blue: it is now a prefab.

14Put the player on the spawn

  1. Click the PlayerSpawn marker and read its Position. (In the real Level 1 it is 0, 0, -9, facing +Z.)
  2. Select Player and type the same Position. Keep Rotation 0, 0, 0.
  3. The camera does not follow yet (that is Phase 4). For now, put it high so you see most of the level. Select Main Camera (if there is none: GameObject → Camera, Tag = MainCamera):
    • Position 0, 16, -26
    • Rotation 35, 0, 0
  4. Save the scene (Ctrl+S / Cmd+S).

15▶ Press Play

Press Play. Click once in the Game view so it gets the keyboard. Open Window → Animation → Animator and select Model so you can watch the states.

Checklist
  • The hero stands on the floor and plays Idle. He does not fall or float.
  • W A S D (or the arrow keys) move him. W runs away from the camera. He turns smoothly toward where he goes.
  • While moving, the Walk animation plays. Hold Shift: he goes faster and plays Run.
  • Keep sprinting for about 3 seconds: he gets tired and walks again. After a short rest he can sprint again.
  • He stops at walls and blocks, and can walk up small steps.
  • In the Animator window, click the small circle next to Win: he waves 3 times, then goes back to idle. Hit and Attack play once. Die: he falls and stays down.
  • No red errors in the Console.

Press Play: you should see the hero run around with the right animation.

16Common problems

ProblemFix
The hero stands in a "T" pose and never moves his arms and legsThe Animator on Model has no Controller. Drag Hero into it. Also check the Avatar.
The hero slides, but always plays IdleThe parameter is not called exactly Speed (step 4), or the blend tree Parameter is not Speed (step 5).
Walk or run plays once and then freezesLoop Time is off for that clip. Tick it in the Animation tab of Hero.fbx and click Apply.
Walk and run look mixed up, or the hero runs when walkingAutomate Thresholds is still on, or the thresholds are not 0 / 0.5 / 1.
The hero moves away from his capsule, or slides on after you stopUntick Apply Root Motion on the Animator.
The hero floats above the floor or sinks into itModel Position must be 0, 0, 0. CharacterController Center = 0, 0.695, 0, Height = 1.35.
The hero falls through the floorThe floor has no collider, or the Player starts below the floor. Select the floor: it needs a Box Collider (or Mesh Collider).
The hero is tiny or giantChange the Scale of Model (not of Player) until he fits the green capsule.
Nothing happens when I press keysClick inside the Game view first. Check that PlayerMotor is on Player and is ticked.
"You are trying to read Input using the UnityEngine.Input class…"Edit → Project Settings → Player → Other Settings → Active Input Handling = Both. Unity restarts.
"The type or namespace name 'VirtualJoystick' could not be found"Do step 8. Check that the file is called VirtualJoystick.cs and the code has namespace GoldRush.
The hero is pinkMaterials tab of Hero.fbx: Import via MaterialDescription, Use Embedded Materials, Apply. The project must be a URP project.
A trigger in the Animator does nothingThe Any State arrow has no condition, or the condition uses the wrong trigger.
After Win / Hit the hero stays in that animationThe arrow back to Locomotion is missing, or Has Exit Time is off on it.
